## What Went Well

Amelia (Developer): "Let's highlight our biggest successes in Epic 6."

**Lightweight Mapbox Static Maps builder was a monumental performance win.**
Instead of pulling in a massive 230KB JS bundle of Mapbox GL JS and rendering an interactive canvas on every community page, we implemented `buildStaticMapUrl`. It compiles community center coordinates, zoom factor, and geo-fence polygons directly into a safe, signed Mapbox Static API URL. 

Charlie (Senior Dev): "This saved us immense client-side bundle weight. informational pages load in under 100ms, search engine crawlers can see the map instantly as an HTML `<img>` tag, and accessibility is solved through localized `alt` tags."

**Circular Drizzle relation imports solved cleanly via separate relations file.**
We avoided circular import loops in Drizzle schemas by defining relationship boundaries solely in `src/lib/db/schema/relations.ts`. The schema tables (areas, communities, properties) remain decoupled at model definition time, and relationships are safely wired at query time.

Elena (Junior Dev): "It made database queries very clean. Drizzle knew exactly how to join communities with areas and properties, and we didn't experience any TypeScript compiler blockages during build time."

**PostGIS ST_Within spatial tagging works beautifully in the sync pipeline.**
Story 6.5 extended the sync pipeline to automatically tag new listings to communities based on coordinates. By leveraging PostGIS, the queries run in milliseconds. The code also honors manual admin overrides by checking a `manualCommunityOverride` boolean flag.

Dana (QA Engineer): "We verified this using geo-fence boundaries in Uvita. A listing in Uvita with exact coordinates inside Serena del Mar was automatically tagged to Serena del Mar, and when manually set to another community by an admin, the override was preserved during sync. Excellent!"

**Green testing practices maintained—pre-existing test failures resolved quickly.**
When adding communities columns and mock data requirements, 12 pre-existing tests broke due to incomplete mocks. Instead of ignoring them, we did a dedicated test quality sprint in PR #158 to update mocks, ensure sitemaps, homepage, and unit toggles remained completely green.

## Challenges and Growth Areas

Amelia (Developer): "Where we struggled and how we can grow."

**Brittle unit testing mock structures.**
Because our unit tests mock the Drizzle client queries individually, whenever we change the DB columns or structure (e.g., adding `status` to `PropertySearchItem` in 6.2), several pre-existing, unrelated test files break. PR #158 was entirely dedicated to fixing 12 broken unit tests across 3 files.

Charlie (Senior Dev): "We are mocking at a too low level. We need a centralized database mock factory like `makeMockProperty()` and `makeMockCommunity()` rather than hardcoding vi.fn() arrays across dozens of spec files. If we don't address this, Epic 7 and 8 will suffer from more mock breaks."

**Mapbox Static URL geo-fence length limits (Risk R-013).**
For highly complex geographic polygons (e.g., communities with 50+ vertices), the URL-encoded path for the Mapbox Static API can exceed HTTP GET length limits (8192 characters). We had to make sure our coordinates precision is limited to 5 decimal places and coordinate arrays are filtered/simplified if needed.

Dana (QA Engineer): "This is a real risk for extremely custom development boundaries. We should implement a coordinate simplification algorithm (like Douglas-Peucker) or cap vertices count at 20 to prevent broken Mapbox images in production."

**PostGIS extension validation in production remains a question.**
Although our local Docker environment has PostGIS enabled, we do not have an automated CI script checking if the PostGIS extensions are enabled on the target cloud database before migration pushes.

Charlie (Senior Dev): "This is why the sync pipeline runbook is so critical. If ST_Within fails in production because someone forgot to run `CREATE EXTENSION postgis;`, the entire sync pipeline halts. We must deliver this runbook at the start of Epic 7."

## Key Insights

1. **Static image overlays are superior to canvas-based interactive maps for static pages.**
Mitigating the Mapbox GL JS bundle bloat through signed server-constructed image URLs is a highly reproducible performance pattern that should be applied to all future static grids.

2. **Decoupled model relations are crucial for clean Drizzle architecture.**
Separating table definitions from relations definitions prevents circular dependency loops, keeps schemas modular, and ensures fast compile times.

3. **Coordinate precision truncation is required for Mapbox Static API URLs.**
Truncating latitude and longitude to 5 decimal places (~1.1 meter precision) preserves map accuracy while drastically reducing the length of GeoJSON overlay strings.

4. **Brittle mock objects slow down epic iterations.**
Schema changes should not require editing 15 different test spec files. A centralized database mock data factory is a critical necessity for developer velocity.
